# 本機文字協助評估

在 feature/apple-ai-correction 分支實作，透過公開 Foundation Models API 與 NSSpellChecker 非同步 API，不啟動命令列模型服務。舊版中文候選重排序模組未接入主輸入流程。

## 方法與結果

research/text-assistance/corpus-200.json 包含 200 筆逐題編寫的合成例句：中文錯字、英文錯字、受保護內容與正確句子各 50 筆。參考答案尚未由獨立人工審查，不能代表真實使用者準確率。模型透過與 app 相同的供應器、驗證器及協調器執行；未操作真實輸入框。

| 類別 | 結果 |
| --- | --- |
| 中文錯字 | 首項建議符合參考 31／50；43 題有建議 |
| 英文錯字 | 首項建議符合參考 50／50；系統拼字基線 49／50 |
| 受保護內容 | 50／50 沒有提出修改 |
| 原本正確 | 44／50 保持原文；6 題收到多餘建議 |

模型狀態為 196 筆完成、4 筆逾時；逾時使用原文或系統拼字。模型／協調器耗時 P50 約 704 毫秒、P95 約 1081 毫秒、P99 約 5120 毫秒。包含系統拼字後 P95 約 1082 毫秒。這不是鍵盤到畫面的延遲，也沒有隔離冷啟動與背景建置負載。

獨立 prediction-20.json 的 20 個英文前綴均取得通過格式檢查的模型或回退建議；18 筆模型完成、2 筆逾時。模型／協調器 P95 約 5075 毫秒，包含系統拼字約 5080 毫秒，另有 350 毫秒輸入停頓。沒有唯一參考續句，因此不計語意正確率。app 先顯示較快的系統建議，模型僅在輸入狀態尚未改變時更新。

原始結果及機器可讀摘要保存在同一研究目錄；initial 檔案保留早期結果，不能當作目前版本數據。早期測試發現檔名副檔名可能被系統拼字改寫，現已將完整檔名與命令旗標納入保護。系統候選附帶空白的情況亦已正規化。無模型煙霧測試確認英文錯字仍有回退建議，而受保護檔名無建議。

## 測試與限制

CandidateRanking 28 項測試涵蓋受保護字串、Unicode 範圍、模型取消／逾時／忙碌、舊結果丟棄、系統拼字候選與詞庫大小邊界。另有 4 項新語料檢查。8 項新增 IMK／KeyHandler 整合測試只編譯，尚未執行。完整無介面檢查亦包含 C++ 122 通過、2 上游跳過，MixedInputCore 15 通過，原有 Python 14 通過與詞庫檢查。

本次曾在獨立 CLI 探針發現 NSSpellChecker 回呼繼承主執行緒隔離而崩潰；已明確標示 Sendable 回呼，再切回主執行緒更新狀態。修正後完成上述 220 筆本機評估，沒有啟動已安裝的輸入法測試。

正式採用前仍需人工確認跨應用選單、組字、焦點切換、Tab／Esc 與原有 F 分層。macOS 13 的回退路徑尚未實機測試。此版不能宣稱可自動修正中文或具備整份文件上下文。

公開 API 參考：[SystemLanguageModel](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel)、[NSSpellChecker](https://developer.apple.com/documentation/appkit/nsspellchecker)。
