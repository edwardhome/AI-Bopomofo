# 無選單、按住式 F 分層

使用者在 ChatGPT 與 Brave 回報 F 分層必須再按 F 才能退出，造成「其實」「七」等注音輸入困難。0.5.2 在按鍵查詢不可用時仍進入分層，沒有收到 key-up 就會停留，與按住操作需求不符。

0.5.3 移除長按分層的候選視窗及提示，保留手動選單工具。門檻為嚴格超過 100 毫秒，且必須確認 F 的硬體按下狀態。改用 CGEventSource.hidSystemState，看到放開或收到 IMK key-up 即退出。不再以第二次 F 當作正常切換操作。讀不到硬體按下狀態則回放 F 並退出等待，保護正常注音，不會無限停留在分層。

限制：尚未在使用者應用中驗證硬體查詢；如果系統不提供此狀態，F 長按仍不可用，但一般注音不應被困住。CLI 的輸入監控預檢為未授權，這不等於輸入法程序的授權狀態，也不能單靠未按 F 時的 false 推論 API 無效。沒有新增全域攔截、監聽其他按鍵、設定 TCC 或修改 Kanata。API 依據：[Apple 事件來源狀態](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid)。

MixedInputCore 20 項測試通過，包含恰好 100 毫秒不進入、101 毫秒確認按住才進入、短按、放開、取消與無法讀取狀態時回放 F。GUI／hosted 測試未執行；仍需使用者在 ChatGPT、Brave 確認短按 F、其實／七、長按 F 搭配數字、放開後恢復中文。
