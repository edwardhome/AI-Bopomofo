# AI注音輸入法 1.0.4

## 問題與比對證據

使用者確認 `1.0.0-dev.1` 的首字母長按可用，但增加時間設定後的 1.0.1、1.0.3 都無法長按 S 轉 s。測試機器已更正為目前 Mac mini。

唯讀核對：已安裝 app 是 1.0.3／build 1003，執行檔 SHA-256 與交付 app 一致，程序啟動時間晚於此次安裝檔時間；沒有執行安裝或重啟。

Git 比對 `6c6e7c65` 與 `c51dfb59` 顯示：

- 可用版本在 `ShiftLetterSession.applying` 收到首字母 repeat 就轉小寫。
- 後來新增設定時，該分支改成只回傳原狀態，依賴控制器外層手勢完成轉換。1.0.3 的回退仍必須先有這個外層手勢，並非原本的獨立 repeat 路徑。
- `menu()` 產生選單內容時會取消手勢。這個查詢方法不代表使用者已操作設定，取消副作用不應放在這裡。

這是增加 UI 時一併改動輸入流程造成的回歸；無介面測試先前未覆蓋「外層手勢不存在但組字仍在」的完整條件。尚未取得實體事件紀錄，不能宣稱已證實現場是哪一個取消入口先發生。

## 修正

恢復組字內的首字母 repeat 轉換，並將起始時間及當次設定門檻保存在不可變的 Shift 組字狀態。放開 Shift 或複製相同組字時保留時間；新字母、編輯及提交仍照原流程結束首字母追蹤。

repeat 在門檻前只消耗，到達門檻後轉小寫一次；後續不追加字母。這條路徑不依賴外層 Timer、接收者快取或按住狀態查詢。Timer 保留作為系統 repeat 尚未出現時的提前轉換途徑，但不再是唯一依賴。

移除 `menu()` 的取消副作用，實際開啟時間設定等操作仍會取消等待。設定介面與 100～1000 毫秒（預設 250）保留，不改 F 分層時間、監聽及退出規則。
